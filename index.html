Project · Django

oauth-dpop-server

An OAuth 2.1 authorization server where every access token is sender-constrained with DPoP (RFC 9449): a token lifted from a log or a proxy is inert without the key it is bound to. The server-side counterpart of dpop_client, tested against it in CI.

  • Authorization Code with mandatory S256 PKCE, Client Credentials, and refresh tokens rotated on every use, with reuse revoking the whole family.
  • The full RFC 9449 proof checklist: jti replay cache, server nonces, cnf.jkt thumbprint binding and authorization-code binding.
  • RFC 9068 JWT access tokens on rotating ES256 keys, plus metadata, introspection, revocation and pushed authorization requests.
  • ninja_dpop, a reusable Django Ninja auth class for resource servers. No hand-rolled cryptography.
  • Python
  • Django
  • OAuth 2.0
  • RFC 9449
  • PostgreSQL

Project · Django

ledger-service

A double-entry ledger over HTTP that moves money atomically, idempotently and append-only, so money is never created or lost, whatever the concurrency, the retries or the crashes.

  • Every transaction's entries sum to zero in every currency, and the database refuses to commit one that does not.
  • Balances are derived from entries, never stored; entries are never updated or deleted, and mistakes are undone with reversals.
  • Every write takes an Idempotency-Key; concurrent postings serialize on row locks taken in a fixed order, without deadlocks or retry loops.
  • Events leave through a transactional outbox, and a reconciliation job re-checks every invariant against the raw tables.
  • Python
  • Django
  • Double entry
  • Idempotency
  • PostgreSQL

How I work

Four practices present in every codebase I own — the reason a large production application stays workable rather than calcifying.

  1. 01

    Architecture that survives the second year

    Clean Architecture with a strict dependency direction, feature modules that can be reasoned about alone, and DI wiring kept out of business logic. The test is simple: can a new person change one feature without reading the other ten?

    • Clean Architecture
    • BLoC
    • get_it
    • 11 modules
  2. 02

    Errors as values, not surprises

    A typed Result<Ok, Err> boundary instead of exceptions thrown across layers. The compiler forces every failure path to be handled at the point it matters, so production surprises become compile-time arguments. The pattern is also published as verdict and verdict_bloc.

    • Typed boundaries
    • Total functions
    • No silent catch
    • verdict
  3. 03

    Generate what shouldn’t be written by hand

    API clients, models, theme code and localization all come out of a source of truth — Swagger, Figma tokens, translation files. ~190K LOC of client code is generated, which means it can’t drift from the contract and nobody wastes a day on a mistyped DTO. Two open-source CLIs cover the gaps in that pipeline: openapi_enum_patch and figma_tokens_gen.

    • Swagger codegen
    • dart_mappable
    • Figma tokens
    • 1,715 keys
  4. 04

    A baseline the team can’t drift below

    Zero-warning static analysis, a custom analyzer plugin for project-specific rules, Conventional Commits, and CI that runs analyze plus the full test suite on every PR with per-branch build artifacts. Standards that are enforced don’t need to be argued about.

    • Zero warnings
    • Custom lints
    • GitHub Actions
    • 132 suites
